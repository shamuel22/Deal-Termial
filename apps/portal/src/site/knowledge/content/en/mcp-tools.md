Use this reference to choose among the 24 MCP tools and supply the inputs allowed by your agent's current permissions.

## Connection and conventions

Connect to `https://your-domain.example/mcp` using Streamable HTTP and `Authorization: Bearer dtk_your_agent_credential`. The model and tool loop run in your client; the server authenticates each request and executes business services. See [MCP connection](/knowledge/mcp).

In the tables, `?` marks optional inputs. Resource IDs are UUIDs. Money is decimal text, such as `"80.00"`; unit prices allow up to four decimal places, such as `"0.2200"`. Delivery dates use `YYYY-MM-DD`. Expiry timestamps include a timezone.

Buyer levels are `search_only` (Search only), `negotiate` (Negotiate only) and `full_autonomy` (Full autonomy, within your authorized limits). Higher buyer levels include lower-level actions. Seller scopes are independent of buyer levels. A valid credential alone does not authorize every listed tool.

### Criteria inputs

`create_request.criteria` contains `category: "food_containers"`, optional `requiredAttributes`, `quantity`, `deliveryAddress`, `deliverBy` and optional `maxTotal`. Its address has `line1`, optional `line2`, `city`, `state` and `postalCode`. Preferences accept `preferredMaterials` and `notes`.

`find_matches.criteria` contains category, optional required attributes, quantity, optional `deliveryState`, optional `deliverBy` and optional `maxTotal`. With `requestId`, it uses saved criteria instead. Missing mandatory product attributes remain unconfirmed. See [offers](/knowledge/offers) for attribute names and allowed values.

Change-request `terms` propose complete [purchase authorization](/knowledge/purchase-authorizations) conditions. They do not alter an active authorization until approved by an owner or administrator.

`publish_offer.product` takes `sku`, `name`, optional `description`, `category: "food_containers"` and `attributes`. The offer takes stock, order limits, shipping regions, lead time, shipping charge, tax rate, price tiers and private negotiation rules. Creation status is `draft` (Draft) or `active` (Active). See [offers](/knowledge/offers) for the full conditions.

Supplier agents cannot approve exceptions to their negotiation rules. A human owner or administrator must act through a console session. See [negotiation](/knowledge/negotiation).

## Results, errors and safe retries

Every tool enforces access on the server through its business service. Responses are JSON text in MCP content blocks. On a domain failure, the tool returns `isError: true` with `{ error: { code, hint } }` plus `message` and optional `details`. Codes are listed in the [REST reference](/knowledge/api).

> **Note:** The current wrapper's validation errors include `code`, `message` and `issues`, but no `hint`. Unexpected errors return `INTERNAL` and a message, also without a hint. Clients must tolerate those shapes.

Read `authorizationCheck` before acceptance, then let acceptance recheck current authority and reservations. Repeat keyed acceptance or cancellation with the same inputs; a conflicting key is rejected. Refund request keys retrieve an existing request for the order. For an uncertain payment, inspect `get_order` and allow reconciliation instead of starting another charge.

> **Important:** PayPal multi-seller vaulting is unavailable for the current integration. `execute_purchase` can complete commercial acceptance while returning `owner_action_required` (Owner payment required). It does not prove payment or delivery. See [payments](/knowledge/payments).
